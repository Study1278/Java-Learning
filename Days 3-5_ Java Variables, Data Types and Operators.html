DAY 3 · Wednesday

Part 1. Primitive types

A variable is a named box in memory. Its type decides how big the box is and what can go inside. Java has 8 primitive types. Today's six are in bold.

TypeSizeRange or detailUse it for
int4 bytes-2,147,483,648 to 2,147,483,647 (about 2.1 billion)Default whole numbers
long8 bytesAbout -9.2 quintillion to 9.2 quintillionWhole numbers above 2.1 billion
float4 bytesAbout 7 digits of precisionDecimals when memory matters
double8 bytesAbout 15 digits of precisionDefault decimals
char2 bytesOne character, single quotes'A', '7'
booleanabout 1 bit of informationtrue or falseConditions
byte, short1, 2 bytes-128 to 127, and -32,768 to 32,767Small numbers, arrays of raw data
How to choose: whole number gives int, unless it could pass 2.1 billion (phone numbers, population, money in paise), then long. Decimal gives double. Yes or no gives boolean.

Three beginner traps

  • long big = 3000000000L; needs the L, otherwise Java treats the number as int and refuses it.
  • float f = 3.14f; needs the f, because decimal literals are double by default.
  • 0.1 + 0.2 is not exactly 0.3 in double. Computers store binary approximations.

Lab: Types.java

public class Types {
    public static void main(String[] args) {
        int age = 21;
        long population = 8000000000L;
        float price = 99.99f;
        double pi = 3.141592653589793;
        char grade = 'A';
        boolean passed = true;

        System.out.println(age + " " + population);
        System.out.println(price + " " + pi);
        System.out.println(grade + " " + passed);

        System.out.println(Integer.MAX_VALUE);       // 2147483647
        System.out.println(Integer.MAX_VALUE + 1);   // overflow: -2147483648
        System.out.println(Long.MAX_VALUE);
        System.out.println(0.1 + 0.2);               // 0.30000000000000004
    }
}

Predict the last 4 lines before running. The overflow line is the one to remember: int wraps around instead of crashing.

Part 2. Type casting: implicit vs explicit

Implicit (widening): automatic and safe

A smaller type fits into a bigger one, so Java converts it for you. Order: byte → short → int → long → float → double.

int i = 10;
double d = i;        // 10.0, automatic
long l = i;          // fine

Explicit (narrowing): you force it and can lose data

A bigger value going into a smaller box needs (type)value. Java makes you write it so you know data may be lost.

double price = 9.99;
// int x = price;        // compile error: possible lossy conversion
int x = (int) price;     // 9, decimals are cut off, NOT rounded
byte b = (byte) 130;     // -126, value wraps around

char and int

Every char is a number (Unicode). 'A' is 65, 'B' is 66, 'a' is 97, '0' is 48.

int code = 'A';              // 65
char c = (char) 66;          // 'B'
char next = (char) ('A' + 1);// 'B'
System.out.println('A' + 1);        // 66 (math, so int)
System.out.println("" + 'A' + 1);   // A1 (string joining)

DAY 4 · Thursday

Part 3. Operators

Your task: one small program that uses all four categories on the same two numbers. We use a = 12 and b = 10.

The four categories

CategoryOperatorsResult type
Arithmetic+ - * / % (also ++ --)A number
Relational== != > < >= <=boolean
Logical&& || !boolean
Bitwise& | ^ ~ << >>A number, works on the bits

% is the remainder: 17 % 5 is 2. Use it for even or odd checks (n % 2 == 0).

&& and || short-circuit: if the left side already decides the answer, the right side is not even evaluated. The single & and | on booleans always evaluate both sides.

How bitwise works, with a = 12 and b = 10

a = 12 = 1100
b = 10 = 1010

a & b  = 1000 = 8     (1 only where both are 1)
a | b  = 1110 = 14    (1 where either is 1)
a ^ b  = 0110 = 6     (1 where they differ)
~a     = -13          (flips all bits: -(a+1))
a << 1 = 11000 = 24   (shift left = multiply by 2)
a >> 1 = 110 = 6      (shift right = divide by 2)

Lab: Operators.java

public class Operators {
    public static void main(String[] args) {
        int a = 12, b = 10;

        System.out.println("--- Arithmetic ---");
        System.out.println(a + b);   // 22
        System.out.println(a - b);   // 2
        System.out.println(a * b);   // 120
        System.out.println(a / b);   // 1
        System.out.println(a % b);   // 2

        System.out.println("--- Relational ---");
        System.out.println(a == b);  // false
        System.out.println(a != b);  // true
        System.out.println(a > b);   // true
        System.out.println(a < b);   // false

        System.out.println("--- Logical ---");
        System.out.println(a > 5 && b > 5);    // true
        System.out.println(a > 20 || b > 5);   // true
        System.out.println(!(a > b));          // false

        System.out.println("--- Bitwise ---");
        System.out.println(a & b);   // 8
        System.out.println(a | b);   // 14
        System.out.println(a ^ b);   // 6
        System.out.println(~a);      // -13
        System.out.println(a << 1);  // 24
        System.out.println(a >> 1);  // 6
    }
}

Extra: change a and b to other numbers, predict every line, then run. Try a++ vs ++a inside a println to see the difference between post and pre increment.

Part 4. Input and output: Scanner

Output

System.out.println("Hello");     // prints and moves to the next line
System.out.print("Hello ");      // prints and stays on the same line
System.out.printf("%.2f%n", 3.14159);   // 3.14, formatted

Input

import java.util.Scanner;

public class Input {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter age: ");
        int age = sc.nextInt();
        System.out.print("Enter marks: ");
        double marks = sc.nextDouble();
        System.out.println(age + " " + marks);
        sc.close();
    }
}
MethodReads
nextInt()One whole number
nextDouble()One decimal number
next()One word (stops at a space)
nextLine()A full line, up to Enter
nextBoolean()true or false

The famous pitfall: nextInt() then nextLine()

System.out.print("Age: ");
int age = sc.nextInt();
System.out.print("Name: ");
String name = sc.nextLine();   // SKIPPED, name is empty

Why it happens: you type 21 and press Enter, so the input is really 21↵. nextInt() takes the 21 but leaves the Enter (the newline) in the buffer. Then nextLine() reads from where it is up to the next Enter, finds it immediately, and returns an empty string. It looks skipped, but it actually read the leftover Enter.

Two fixes

// Fix 1: eat the leftover newline
int age = sc.nextInt();
sc.nextLine();                    // throw away the rest of that line
String name = sc.nextLine();      // now works

// Fix 2: always read lines, then convert
int age2 = Integer.parseInt(sc.nextLine());
String name2 = sc.nextLine();

Also know: typing letters into nextInt() throws InputMismatchException.

2. Swap two numbers: with and without a temp variable

Show a solution
public class Swap {
    public static void main(String[] args) {
        int a = 5, b = 9;

        // With a temp variable
        int temp = a;
        a = b;
        b = temp;
        System.out.println(a + " " + b);   // 9 5

        // Without temp (using + and -)
        a = a + b;     // 14
        b = a - b;     // 9
        a = a - b;     // 5
        System.out.println(a + " " + b);   // 5 9

        // Without temp (using XOR)
        a = a ^ b;
        b = a ^ b;
        a = a ^ b;
        System.out.println(a + " " + b);   // 9 5
    }
}

The + and - trick can overflow for huge ints. The XOR trick cannot. The temp variable version is the clearest and is what real code uses.

3. Calculator with switch

Show a solution
import java.util.Scanner;

public class Calculator {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter two numbers: ");
        double x = sc.nextDouble();
        double y = sc.nextDouble();
        System.out.print("Operator (+ - * /): ");
        char op = sc.next().charAt(0);

        switch (op) {
            case '+': System.out.println(x + y); break;
            case '-': System.out.println(x - y); break;
            case '*': System.out.println(x * y); break;
            case '/':
                if (y == 0) System.out.println("Cannot divide by zero");
                else System.out.println(x / y);
                break;
            default: System.out.println("Invalid operator");
        }
    }
}

Without break, Java keeps running into the next case (fall-through). Forgetting it is the number one switch bug.

4. Temperature converter

import java.util.Scanner;

public class Temperature {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Celsius: ");
        double c = sc.nextDouble();

        System.out.printf("%.1f F = %.1f C%n", f2, c2);
    }
}

Part 6. LeetCode: Two Sum and Reverse Array

Two Sum (LC 1, Easy)

Given an array and a target, return the indexes of the two numbers that add up to the target. Example: [2, 7, 11, 15], target 9 gives [0, 1].

Step 1: brute force, O(n²). Try every pair.

public int[] twoSum(int[] nums, int target) {
    for (int i = 0; i < nums.length; i++) {
        for (int j = i + 1; j < nums.length; j++) {
            if (nums[i] + nums[j] == target) {
                return new int[]{i, j};
            }
        }
    }
    return new int[]{};
}

Step 2: HashMap, O(n). For each number, the partner you need is target - num. Keep a map of numbers you have already seen with their index. If the partner is in the map, you are done. One pass, and each lookup is fast.

import java.util.*;

public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // value -> index
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) {
            return new int[]{seen.get(need), i};
        }
        seen.put(nums[i], i);
    }
    return new int[]{};
}

Trace it on [2, 7, 11, 15], target 9: at 2, need 7, map empty, store 2. At 7, need 2, found at index 0, return [0, 1].

Reverse Array: two-pointer swap in place

Put one pointer at the start and one at the end. Swap, move both inward, stop when they meet. No second array needed, so extra memory is O(1).

public static void reverse(int[] arr) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        int temp = arr[left];
        arr[left] = arr[right];
        arr[right] = temp;
        left++;
        right--;
    }
}
// [1, 2, 3, 4, 5]  ->  [5, 4, 3, 2, 1]

After you can do it by hand, try LeetCode 344 Reverse String, which is the same idea on a char array.
