DAY 25 · Thursday

Part 1. Inheritance with extends

Inheritance lets a new class reuse an existing one. The existing class is the parent (superclass). The new class is the child (subclass). The child gets the parent's non-private fields and methods automatically, and can add its own. Use it when the sentence "Dog is an Animal" makes sense.

class Animal {
    String name = "Animal";
    void makeSound() {
        System.out.println("Some sound");
    }
}

class Dog extends Animal {
    void fetch() {                 // only Dog has this
        System.out.println(name + " fetches");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.makeSound();   // inherited from Animal
        d.fetch();       // Dog's own
    }
}
Remember: private members are not inherited for direct use (the child cannot write name if it is private, it must use a getter). Java allows only one parent class per class (single inheritance), but a chain is fine.

Part 2. The super keyword

super means "the parent part of this object". Two uses:

Use 1: super(...) calls the parent constructor

When you create a Dog, the Animal part is built first. If the parent has a constructor with parameters, the child must call it, and super(...) must be the first line.

class Animal {
    String name;
    Animal(String name) {
        this.name = name;
        System.out.println("Animal constructor");
    }
}
class Dog extends Animal {
    Dog(String name) {
        super(name);               // first line
        System.out.println("Dog constructor");
    }
}
// new Dog("Bruno") prints:
// Animal constructor
// Dog constructor
Trap: if you write no super(...), Java adds super() for you. If Animal has no no-argument constructor, you get a compile error. Fix: call super(name) yourself.

Use 2: super.method() calls the parent's version

class Dog extends Animal {
    void makeSound() {
        super.makeSound();          // Some sound
        System.out.println("Woof"); // then add more
    }
}

DAY 26 · Friday

Part 3. Method overriding and @Override

Overriding means a child class gives its own version of a method the parent already has. Same method name, same parameters.

class Animal {
    void makeSound() { System.out.println("Some sound"); }
}
class Dog extends Animal {
    @Override
    void makeSound() { System.out.println("Woof"); }
}
class Cat extends Animal {
    @Override
    void makeSound() { System.out.println("Meow"); }
}

Animal a = new Dog();
a.makeSound();    // Woof  (runtime decides, based on the real object)

That last line is the heart of polymorphism: the variable type is Animal, but Java runs the version from the actual object (Dog).

Rules for overriding

  • Same name and same parameter list as the parent method.
  • Return type must be the same (or a subtype of it).
  • Access cannot be more restrictive: a public parent method cannot become private in the child.
  • You cannot override private, static or final methods.

Why always write @Override

class Dog extends Animal {
    void makeSond() { ... }   // typo: silently creates a NEW method
    @Override
    void makeSond() { ... }   // compile error: nothing to override. Typo caught!
}
OverloadingOverriding
WhereSame classParent and child

Part 4. The final keyword

final means "cannot be changed". It works in three places:

On aMeaningExample
variableValue can be set oncefinal int MAX = 10;
methodSubclasses cannot override itfinal void login() {}
classNobody can extend itfinal class String

Lab: see the compile errors yourself

class Animal {
    final void breathe() { System.out.println("Breathing"); }
}
class Dog extends Animal {
    // @Override
    // void breathe() { }   // uncomment: error, cannot override final method
}

final class Cat { }
// class Kitten extends Cat { }  // uncomment: error, cannot inherit from final

Why use it? Security and safety. Java's own String is final so nobody can build a subclass that changes how strings behave.

DAY 27 · Saturday

Part 5. The instanceof operator

When a variable has the parent type, the real object may be any child. Casting to the wrong child crashes the program with ClassCastException. instanceof checks the real type first and returns true or false.

Animal animal = new Dog();

if (animal instanceof Dog) {
    Dog d = (Dog) animal;   // safe cast
    d.fetch();
}

Animal other = new Cat();
Dog bad = (Dog) other;      // crashes: ClassCastException

Newer Java (16 and above) lets you combine check and cast:

if (animal instanceof Dog d) {
    d.fetch();              // d is already a Dog here
}
Good to know: null instanceof Dog is always false, and a GoldenRetriever object is instanceof Dog and Animal, because it is all of them.

Part 6. Build: Animal, Dog, GoldenRetriever

Three levels of inheritance. Each level overrides makeSound(), and GoldenRetriever adds its own fetch().

class Animal {
    protected String name;
    Animal(String name) { this.name = name; }
    void makeSound() { System.out.println(name + ": some sound"); }
}

class Dog extends Animal {
    Dog(String name) { super(name); }
    @Override
    void makeSound() { System.out.println(name + ": Woof"); }
}

class GoldenRetriever extends Dog {
    GoldenRetriever(String name) { super(name); }
    @Override
    void makeSound() {
        super.makeSound();                       // Dog's Woof first
        System.out.println(name + ": (friendly bark)");
    }
    void fetch() { System.out.println(name + " fetches the ball"); }
}

public class Main {
    public static void main(String[] args) {
        Animal[] zoo = {
            new Animal("Generic"),
            new Dog("Bruno"),
            new GoldenRetriever("Goldie")
        };
        for (Animal a : zoo) {
            a.makeSound();                       // runtime picks the version
            if (a instanceof GoldenRetriever g) {
                g.fetch();                       // only for this type
            }
        }
    }
}
