Part 1. What is a class?

A class is a blueprint. An object is a real thing built from that blueprint. A class has two kinds of members:

  • Fields: variables that store data (what the object has).
  • Methods: functions that do work (what the object does).
public class Student {
    String name;          // field
    int age;              // field

    void introduce() {    // method
        System.out.println("Hi, I am " + name);
    }
}

Part 2. Access modifiers

Beginner picture: imagine a house. private is your bedroom (only you). Default is the family area (people living in the same house, the package). protected is the family area plus your children who moved out (subclasses). public is the front garden (everyone).

An access modifier decides who may use a field or method. Think of it as a door lock.

ModifierSame classSame packageSubclass (other package)Everyone else
publicYesYesYesYes
protectedYesYesYesNo
default (nothing)YesYesNoNo
privateYesNoNoNo
Rule of thumb: make fields private and give access through public methods (getters and setters). This is called encapsulation, and you will see it in every Java project.

Part 4. Object creation with new

Take this one line: BankAccount acc = new BankAccount();

  1. new reserves memory on the heap for a BankAccount object.
  2. The fields get their starting values.
  3. new returns a reference (like an address) to that object.
  4. The variable acc lives on the stack and stores the reference, not the object.

DAY 23 · Tuesday

Part 6. Constructors

A constructor is a special method that runs automatically when you write new. Its job is to set up the object's starting values. Rules: it has the same name as the class and no return type (not even void).

1. Default constructor

If you write no constructor, Java quietly adds an empty one for you. That is why new Student() worked before you ever wrote a constructor.

Trap: the moment you write any constructor yourself, Java stops adding the free one. Then new Student() fails unless you write it too.

2. Parameterized constructor

public class Student {
    String name;
    int age;

    Student(String n, int a) {   // takes values
        name = n;
        age = a;
    }
}
// Student s = new Student("Ravi", 20);

3. Overloading constructors

You can write several constructors in one class as long as their parameter lists differ (different count or types). Java picks the one that matches the call.

Student()                  { name = "Unknown"; age = 0; }
Student(String n)          { name = n; age = 0; }
Student(String n, int a)   { name = n; age = a; }

new Student();             // calls the first
new Student("Ravi");       // calls the second
new Student("Ravi", 20);   // calls the third

Part 7. The this keyword

this means "the current object". You use it two ways.

Use 1: separate a field from a parameter with the same name

Student(String name, int age) {
    this.name = name;   // left: the field, right: the parameter
    this.age = age;
}

Without this, name = name just assigns the parameter to itself and the field stays empty. This is the most common beginner bug.

Use 2: call one constructor from another

Student(String name) {
    this(name, 0);       // must be the FIRST line
}
Student(String name, int age) {
    this.name = name;
    this.age = age;
}

This avoids copying the same code into every constructor.

Part 8. The static keyword

Normal fields belong to each object. A static member belongs to the class itself, and every object shares the same one.

Static field: one copy shared by all

class Student {
    static int count = 0;   // shared
    String name;            // one per object

    Student(String name) {
        this.name = name;
        count++;            // every new object adds 1
    }
}
new Student("A"); new Student("B");
System.out.println(Student.count);  // 2

Call static members with the class name: Student.count.

Static method

Runs without creating an object, like Math.sqrt(9). Rule: a static method cannot use non-static fields directly, because there may be no object at all.

static int getCount() { return count; }   // fine
// static void bad() { System.out.println(name); }  // error: no object

Static block

Runs once, when the class is first loaded. That happens before any object is created and before the body of main runs.

class Demo {
    static { System.out.println("Class loaded"); }
    public static void main(String[] args) {
        System.out.println("main runs");
    }
}
// Output:
// Class loaded
// main runs

Part 9. Build the complete BankAccount

Requirements from your plan: fields accountNumber and balance; methods deposit(amount), withdraw(amount) with an insufficient funds check, and getBalance(). This class is the base for Sprint 4 (exception handling), so keep it clean. This combines all three days: private fields, constructor with this, and a static counter.

public class BankAccount {
    private static int totalAccounts = 0;
    private String accountNumber;
    private double balance;

    static { System.out.println("BankAccount class loaded"); }

    public BankAccount(String accountNumber, double balance) {
        this.accountNumber = accountNumber;
        this.balance = balance;
        totalAccounts++;
    }
    public BankAccount(String accountNumber) {
        this(accountNumber, 0);
    }

    public void deposit(double amount) {
        if (amount <= 0) {
            System.out.println("Deposit must be positive");
            return;
        }
        balance += amount;
    }

    public boolean withdraw(double amount) {
        if (amount <= 0) {
            System.out.println("Withdraw must be positive");
            return false;
        }
        if (amount > balance) {
            System.out.println("Insufficient funds");
            return false;
        }
        balance -= amount;
        return true;
    }

    public double getBalance() { return balance; }
    public String getAccountNumber() { return accountNumber; }
    public static int getTotalAccounts() { return totalAccounts; }
}

Test it

public class Main {
    public static void main(String[] args) {
        BankAccount a = new BankAccount("A101", 1000);
        BankAccount b = new BankAccount("B202");
        a.deposit(500);
        a.withdraw(2000);                       // Insufficient funds
        a.withdraw(300);
        System.out.println(a.getBalance());     // 1200.0
        System.out.println(b.getBalance());     // 0.0
        System.out.println(BankAccount.getTotalAccounts()); // 2
    }
}
Why check for insufficient funds: without the check, a withdraw could make the balance negative. Right now we print a message and return false. In Sprint 4 you will replace this with an exception.

Extra practice: add a transfer(BankAccount to, double amount) method that withdraws from this account and deposits into the other only if the withdraw worked.
