DAY 28 · Sunday

Polymorphism means "many forms": one name, different behavior. Java has two kinds, and the difference is when Java decides which method to run.

Part 1. Compile-time polymorphism: overloading

Several methods share one name but have different parameters. The compiler picks the right one while compiling, using the argument types you pass. You already did this with add() in Sprint 2.

class Calculator {
    int add(int a, int b)           { return a + b; }
    double add(double a, double b)  { return a + b; }
    int add(int a, int b, int c)    { return a + b + c; }
}

Calculator c = new Calculator();
c.add(2, 3);        // int version
c.add(2.5, 3.5);    // double version
c.add(1, 2, 3);     // three-parameter version

Changing only the return type is not overloading and does not compile.

Important trap: the compiler uses the variable's type, not the real object. 
static void feed(Animal a) { System.out.println("Animal feed"); }
static void feed(Dog d)    { System.out.println("Dog feed"); }

Animal x = new Dog();
feed(x);    // prints "Animal feed", because x is declared as Animal

Part 2. Runtime polymorphism: overriding

A child class overrides a parent method. When you call it through a parent-typed variable, Java decides at runtime which version runs, based on the actual object, not the variable type.

class Animal { void makeSound() { System.out.println("Some sound"); } }
class Dog extends Animal {
    @Override void makeSound() { System.out.println("Woof"); }
}
class Cat extends Animal {
    @Override void makeSound() { System.out.println("Meow"); }
}

Animal a = new Dog();
a.makeSound();      // Woof
a = new Cat();
a.makeSound();      // Meow   (same variable, same call, new behavior)

Also calledOverloading, static bindingOverriding, dynamic binding

DAY 29 · Monday

Part 3. Abstract class and abstract methods

An abstract class is an incomplete class. It is a base for children and cannot be created directly. It can hold both regular methods (with a body) and abstract methods (no body, just a promise).

abstract class Shape {
    String color = "Red";

    abstract double area();          // no body

    void describe() {                // normal method
        System.out.println(color + " shape, area " + area());
    }
}

class Square extends Shape {
    double side = 4;
    @Override
    double area() { return side * side; }   // must implement
}

// Shape s = new Shape();   // compile error: Shape is abstract
Shape s = new Square();     // fine
s.describe();               // Red shape, area 16.0
  • A child must implement all abstract methods, or be declared abstract itself.
  • Abstract classes can have constructors, fields and normal methods.
  • You cannot combine abstract with final or private on a method.

Part 4. Interface: implements and default methods

An interface is a pure contract: a list of methods a class promises to provide. A class signs the contract with implements.

interface Drawable {
    void draw();                         // public abstract automatically

    default void show() {                // Java 8+: method with a body
        System.out.println("Showing...");
        draw();
    }
}

class Circle implements Drawable {
    @Override
    public void draw() { System.out.println("Drawing circle"); }
}

new Circle().show();     // Showing... / Drawing circle
  • Methods in an interface are public by default, so the implementing method must be written public.
  • Fields in an interface are automatically public static final (constants).
  • A class can implement many interfaces: class A implements X, Y.
  • A default method gives existing classes new behavior without breaking them. A class may override it.
Common error: writing void draw() without public in the class. The compiler says you are trying to assign weaker access privileges.

Part 5. Abstract class vs interface

This is a very common interview question. Learn the table, then be able to explain each row in your own words.

How to choose: if the children share fields and code (Circle, Rectangle share a color), use an abstract class. If unrelated classes need the same ability (Bird and Plane can both Flyable), use an interface.

Two interfaces in one class:

interface Flyable { void fly(); }
interface Swimmable { void swim(); }
class Duck implements Flyable, Swimmable {
    public void fly()  { System.out.println("Duck flies"); }
    public void swim() { System.out.println("Duck swims"); }
}

Part 6. Build: Shape, Circle, Rectangle, Triangle

Shape declares an abstract area(). Each child writes its own formula. Then one array of mixed Shape references shows runtime polymorphism working across all three.

abstract class Shape {
    abstract double area();
}

class Circle extends Shape {
    double radius;
    Circle(double radius) { this.radius = radius; }
    @Override
    double area() { return Math.PI * radius * radius; }
}

class Rectangle extends Shape {
    double width, height;
    Rectangle(double w, double h) { width = w; height = h; }
    @Override
    double area() { return width * height; }
}

class Triangle extends Shape {
    double base, height;
    Triangle(double b, double h) { base = b; height = h; }
    @Override
    double area() { return 0.5 * base * height; }
}

public class Main {
    public static void main(String[] args) {
        Shape[] shapes = {
            new Circle(3),
            new Rectangle(4, 5),
            new Triangle(6, 2)
        };
        for (Shape s : shapes) {
            System.out.println(s.getClass().getSimpleName()
                + " area = " + s.area());
        }
    }
}
Show expected output 
Circle area = 28.274333882308138
Rectangle area = 20.0
Triangle area = 6.0

The loop calls s.area() on a Shape variable, yet three different formulas run. Adding a new shape later (say Square) needs no change in the loop.

Extra practice: turn area() into an interface method Measurable and compare. Add a normal method describe() in Shape that prints the area, and call it on each shape. Sum all areas in the loop and print the total.
